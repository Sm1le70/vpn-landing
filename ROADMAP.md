# Роадмап: исправления и новые функции

Временный документ. Удалить, когда все задачи закрыты (последняя задача роадмапа).

Основа — анализ кода от 26.09.2026. Сервис работает в проде, пользователей меньше 1000: изменения схемы БД только добавляющие (через `addColumn` / `CREATE TABLE IF NOT EXISTS`), существующие данные не ломаем.

## Как работаем

- Одна задача — одна ветка (`fix/…`, `feat/…`, `chore/…`) и один PR в `main`. Задачи нарезаны так, чтобы каждую можно было сделать за одну сессию.
- В каждом PR: тесты на изменённую логику, `npm test` и `npm run check-wording` зелёные, README обновлён, если меняется поведение или настройка.
- Новые тексты для клиентов проходят `npm run check-wording`.
- Статус задачи в этом файле меняется в том же PR: `[ ]` → `[x]`.
- Фазы идут по порядку. Внутри фазы порядок — рекомендуемый; зависимости указаны явно.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Служебные алерты | Отдельная тема «Алерты» в группе поддержки Telegram (как «Обращения») |
| Chargeback | Алерт + автоматическое снятие дней заказа; отключение — вручную админом |
| Напоминания | За 3 дня и за 1 день до окончания; email + Telegram (если аккаунт привязан) |
| Промокоды | Скидка в % или ₽; лимит использований, срок, тарифы, один раз на клиента |
| Кабинет | Выход на всех устройствах, список и отвязка устройств, перевыпуск ссылки |
| Пробный период | Блоклист одноразовых почтовых доменов (HWID-проверка остаётся) |
| Чеки 54-ФЗ | Не требуется — не входит в роадмап |
| Лендинг | Шрифты локально вместо Google Fonts; Open Graph, canonical, sitemap |

**Вне рамок:** реферальная программа, смена email в кабинете, лимит пробных периодов на IP, онлайн-касса.

## Фаза 1. Ошибки и алерты

- [x] **1.1. Ручное продление/выдача пробному клиенту** — `fix/grant-trial-user`
  - `changeDays` (`src/admin/service.js`): при положительном продлении клиента с `plan_kind = 'trial'` ставить `plan_kind = 'paid'` и `hwidDeviceLimit = paidDeviceLimit`.
  - Иначе HWID-проверка может отключить выданную вручную подписку, лимит устройств остаётся 1, в кабинете — «Пробный период».
  - Продление поддержкой на 1–7 дней тоже переводит в `paid`. Подписка, отключённая проверкой устройств пробного периода, включается; отключённая администратором — нет.
- [x] **1.2. Не сбрасывать индивидуальный лимит устройств при оплате** — `fix/keep-device-limit`
  - `applyPaidOrder` (`src/subscriptions.js`): новый лимит = `max(текущий, paidDeviceLimit)`; 0 (без лимита) сохраняется. То же правило — при переводе пробного в платные (1.1).
- [x] **1.3. Сверка транзакции с заказом** — `fix/verify-transaction`
  - `markOrderPaid`: транзакция этого заказа (ID совпадает с `platega_tx_id`, а если он ещё не сохранён — `payload` = номер заказа), сумма обязательна, валюта (если указана) — RUB.
  - Несовпадение → `error` на заказе и алерт (после 1.5 — в Telegram).
- [x] **1.4. Окно сверки неоплаченных заказов** — `fix/order-sync-window`
  - Фоновая сверка: заказы `pending`, у которых не истёк `payment_expires_at` (+1 ч запаса; если срок неизвестен — младше `ORDER_PAY_HOURS`), а не только младше 2 часов. Старше 2 ч — раз в 15 минут.
  - ~~Однократная сверка отменённых заказов~~ — не нужна: автозакрытие уже сверяет заказ с Platega перед отменой, а `CANCELED` от Platega окончательный.
- [x] **1.5. Алерты в теме «Алерты»** — `feat/alerts`
  - Модуль по образцу `src/tgnotify.js`: очередь, повторы, тема создаётся ботом, ID хранится в `settings`. Без бота — только лог.
  - События: заказ завис в `paid` дольше 10 мин / ошибка выдачи; несовпадение суммы (1.3); chargeback (1.6); Remnawave или Platega недоступны N раз подряд (с антиспамом: одно сообщение и «восстановлено»).
  - Флажок в **Настройках** админки.
- [x] **1.6. Chargeback: автоснятие дней + алерт** — `fix/chargeback` (после 1.5)
  - Callback `CHARGEBACKED` (`src/server.js`): если заказ был `applied` — снять `days` заказа (как `remove_days` при возврате), запись в журнал от имени `system`, алерт со ссылкой на клиента.
  - Повторный callback не снимает дни второй раз. Статус `CHARGEBACKED` перепроверяется через API Platega.
- [x] **1.7. Статистика по московскому времени** — `fix/stats-timezone`
  - `stats()` (`src/admin/service.js`): «сегодня» и дневной график — по московским суткам (неделя и месяц — скользящие 7/30 суток). Фильтр платежей по датам (и CSV) — тоже.

## Фаза 2. Безопасность

- [x] **2.1. Лимиты кода входа на email** — `fix/login-code-limits`
  - Не больше 10 писем с кодом и 15 неверных вводов на email за скользящие 24 ч (таблица `login_events`, чистится вместе с истёкшими кодами и при удалении аккаунта).
  - Понятные сообщения клиенту; постоянные коды (`login-code --permanent`) не затрагиваются.
- [x] **2.2. Запрет демо-режима админки в проде** — `fix/demo-flag-guard`
  - При `DEMO_ADMIN_NO_2FA=true` и https `SITE_URL` (или `NODE_ENV=production`) — ошибка запуска с пояснением.
- [x] **2.3. CSP и HSTS** — `feat/security-headers`
  - Сайт: `script-src 'self'`, стили/шрифты — свои (после 5.1 без Google Fonts), `frame-ancestors 'none'`.
  - Админка: строгий CSP, iframe письма — как сейчас.
  - HSTS при https `SITE_URL`.
  - Проверить в демо и в браузере, что кабинет, QR и админка работают.
- [x] **2.4. Проверка отправителя в обращениях** — `feat/support-auth-results`
  - Результаты SPF/DKIM/DMARC — из поля `authentication`, которое Resend вычисляет при приёме (надёжнее заголовка `Authentication-Results` из самого письма). Подтверждён — только при `dmarc=pass`.
  - В карточке обращения — предупреждение «отправитель не подтверждён», если DMARC/SPF не прошли; такое письмо не привязывается к аккаунту автоматически.
- [x] **2.5. Лимит размера вложений при потоковой отдаче** — `fix/attachment-size`
  - Обрывать передачу после 25 МБ, даже если `Content-Length` не пришёл (`src/admin/support.js`).
- [x] **2.6. Лимит продлений для роли «Поддержка»** — `fix/support-extend-cap`
  - Не больше 7 дней суммарно на клиента за 30 дней (по журналу; роль пишется в запись продления). Админа не касается.
- [x] **2.7. Блоклист одноразовых почт для пробного периода** — `feat/trial-disposable-block`
  - Список доменов в `config/disposable-domains.txt` (+ поддомены); пробный период для них недоступен с понятным сообщением. Оплата не ограничивается.
- [x] **2.8. Шифрование резервных копий** — `feat/backup-encryption`
  - `scripts/backup.sh`: необязательное шифрование `age` публичным ключом (`BACKUP_AGE_RECIPIENT`); восстановление расшифровывает. README: хранить приватный ключ вне сервера.

## Фаза 4. Новые функции

- [ ] **4.1. Напоминания об окончании подписки** — `feat/expiry-reminders`
  - За 3 дня и за 1 день; дни настраиваются в админке (**Настройки**), там же выключатель.
  - Email всегда; Telegram — если аккаунт привязан (ошибка 403 «клиент остановил бота» не считается сбоем).
  - Таблица отправленных напоминаний (пользователь + дата окончания + тип): после продления цикл начинается заново, дублей нет, перезапуск не шлёт повторно.
  - Пробный период тоже получает напоминание (со ссылкой на тарифы). Отключённым админом — не шлём.
- [ ] **4.2. Промокоды** — `feat/promo-codes` (можно разбить на 2 PR: backend + админка)
  - Таблицы кодов и использований. Код: скидка % или ₽, лимит использований, срок действия, список тарифов (пусто — все), активен/выключен.
  - Один раз на клиента. Итоговая цена не ниже 1 ₽ (проверить минимум Platega).
  - Кабинет: поле «Промокод» с проверкой и новой ценой до оплаты. Заказ хранит код и сумму до скидки; использование засчитывается при оплате, не при создании заказа.
  - Админка: раздел «Промокоды» (роль «Администратор»), статистика использований, промокод в карточке заказа и CSV, журнал действий.

- [ ] **4.3. Кабинет: выход на всех устройствах** — `feat/cabinet-logout-all`
  - Удаляет все сессии пользователя, кроме (по выбору) текущей.

  - Список HWID-устройств (платформа, модель, дата) и удаление одного устройства. Проверить эндпоинт удаления одного устройства в API Remnawave 3.3.
